# I2 — Cache do blog em `_headers` + blog no `llms.txt` (+ conferir sitemap/robots) (Onda 1, Infra)

**Objetivo.** Regras de cache para o blog no `frontend/_headers` (Cloudflare Workers static assets) e a entrada do blog no `llms.txt`,
sem quebrar os testes que leem esses arquivos.

## Passo 0 — ler
`docs/blog/fichas/_REGRAS.md`; `frontend/_headers` (inteiro, 40 linhas); `frontend/llms.txt`; `frontend/robots.txt`;
`frontend/scripts/seo.test.mjs:70-150` e `frontend/scripts/staging.test.mjs:1-50` (o que eles exigem de `_headers`, `llms.txt`, sitemap, robots);
`frontend/scripts/build-blog.js:243-254` (o build já injeta as URLs do blog no `dist/sitemap.xml`).
Confirme a sintaxe na doc oficial: https://developers.cloudflare.com/workers/static-assets/headers/ (WebFetch). Ponto a conferir:
quando duas regras casam, os valores do mesmo cabeçalho são **somados**; `! Nome` remove o valor herdado. Verifique se o mesmo bloco
pode ter `! Cache-Control` e depois `Cache-Control: …`. Se a doc disser que não, informe no relatório e use a alternativa que a doc indicar.

## Dono de (só estes)
- EDITA `frontend/_headers`
- EDITA `frontend/llms.txt`
- CRIA `frontend/scripts/blog-infra.test.mjs`
- Proibido: `robots.txt`, `sitemap.xml` (só conferir; se precisar mudar, relatar), `seo.test.mjs`, `staging.test.mjs`, `build*.js`.

## Requisitos
1. `_headers`: acrescentar **depois** do bloco `/*` (fim do arquivo), com um comentário curto em português explicando o porquê (posts mudam pouco;
   o índice muda a cada post novo):
   ```
   /blog/*
     Cache-Control: public, max-age=3600, stale-while-revalidate=86400

   /blog.css
     Cache-Control: public, max-age=3600, stale-while-revalidate=86400

   /blog/index.json
     ! Cache-Control
     Cache-Control: public, max-age=300
   ```
   Sintaxe: caminho sem indentação, cabeçalhos indentados com 2 espaços, linha em branco entre blocos. Nenhum `X-Robots-Tag` depois do `/*`
   (o `staging.test.mjs` proíbe). Não mexer nas regras existentes.
2. `llms.txt`: em "## Páginas públicas", nova linha
   `- [Blog da LAIFT](https://laift.com.br/blog): posts públicos sobre a Liga, os módulos da plataforma e publicações de campanhas de saúde, como o Outubro Rosa.`
   Manter `# LAIFT` na 1ª linha e o resto como está.
3. Conferir (não editar): `robots.txt` não bloqueia `/blog`; `node scripts/build.js` gera `dist/sitemap.xml` com `https://laift.com.br/blog` e
   as URLs `/blog/<slug>` **sem** `.html`. Relatar o resultado.
4. `scripts/blog-infra.test.mjs` (`node:test` + `node:assert/strict`, cabeçalho de copyright, ESM, lê arquivos com `fs`): testa
   (a) o bloco `/blog/*` tem exatamente o Cache-Control pedido; (b) idem `/blog.css`; (c) o bloco `/blog/index.json` tem `! Cache-Control`
   antes de `Cache-Control: public, max-age=300` e vem **depois** do bloco `/blog/*`; (d) nenhum `X-Robots-Tag` depois de `\n/*\n`;
   (e) `llms.txt` contém `https://laift.com.br/blog`; (f) `robots.txt` não tem `Disallow: /blog`.
   Use um parser simples de blocos (caminho na coluna 0, linhas indentadas abaixo), como o do `seo.test.mjs:112-117`.

## Aceite (de `frontend/`, Bash)
```
node --test scripts/blog-infra.test.mjs scripts/seo.test.mjs scripts/staging.test.mjs   # tudo verde
node scripts/build.js && grep -c 'laift.com.br/blog' dist/sitemap.xml                 # >= 2
```
Relatório conforme `_REGRAS.md` (≤ 12 linhas), incluindo o que a doc da Cloudflare diz sobre `!` + valor novo no mesmo bloco (com link).
